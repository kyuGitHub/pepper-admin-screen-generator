# 디지털어드민 화면 제너레이터 · PM 파일럿 가이드

## 목적
PPT 화면설계서(화면당 30분~3시간)를 "요청서 → Claude → 클릭 편집 → URL 공유 → 화면정의서"로 바꿔, 화면 하나를 10분 안에 만들고 개발자가 추가 질문 없이 착수할 수 있는지 확인한다.

## 준비 (관리자, 10분)
1. Supabase 대시보드 → Authentication → Users → **Invite user** 로 PM 이메일 초대. (Authentication → Providers → Email 에서 공개 가입은 꺼 둔다.)
2. 초대 메일의 링크를 열면 비밀번호 설정 화면이 뜬다. 이후 운영 URL에서 이메일/비밀번호로 로그인.
3. 각자 Claude(Max) 계정 준비. 프로젝트 지식에 `app/src/lib/schemaGuide.md`를 넣어 두면 프롬프트가 짧아진다(선택).

## 파일럿 과제 (PM 1인당 1시간)
| 단계 | 할 일 | 산출물 |
| --- | --- | --- |
| 1 | 소매금융 통합시스템에서 맡은 화면 1개를 고른다 (목록 1 + 상세 1이면 더 좋다) | 화면명, 현업 요구 캡처/목록 |
| 2 | [요청서 만들기]에 적고 [프롬프트 복사] → Claude → JSON | 요청서 .md, JSON |
| 3 | [새 화면 올리기] → 저장 → 화면 열기 | 화면 URL |
| 4 | [편집]으로 라벨·버튼·필드를 고치고 저장. 케이스가 있으면 [복제] | 수정된 화면 |
| 5 | [내보내기 ▾ → URL 복사]로 PM리더에게 검토 요청 | 검토 코멘트 |
| 6 | [화면정의서 열기] → PDF 저장, 개발자에게 전달 | 화면정의서 |

## 측정 항목 (파일럿 시트에 기록)
- 화면 1개 소요 시간 (요청서 시작 ~ 화면정의서 전달)
- Claude 재요청 횟수, 편집기에서 손으로 고친 항목 수
- 개발자가 화면정의서를 보고 추가로 물어본 항목 수 (목표 0)
- 막힌 지점: 없는 블록/컴포넌트, 틀린 용어, 편집기에서 안 되는 조작

## 합격 기준 (PRD 성공 지표)
- 1시간에 화면 컨셉 10개 이상
- 파일럿 PM 전원이 최소 1개 화면을 끝까지 완료
- 개발 착수 회의에서 화면정의서만으로 추가 질문 없이 통과한 화면 비율 50% 이상

## 피드백 수집
- 막힌 지점은 그 화면을 [복제]해 제목 끝에 "(피드백)"을 붙이고, 편집기 화면 제목 아래 보조 문구나 소제목에 내용을 적어 둔다. 또는 팀 채널에 URL + 한 줄.
- 주 1회 모아서 블록/컴포넌트 추가 우선순위를 정한다.
